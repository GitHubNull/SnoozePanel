# 01-代理工作规范

> 面向 AI 编程代理（Qoder / Cursor / Copilot 等）：进入本仓库做维护任务前**必读**。
> 违反本规范的操作会被要求返工。

## 第一原则

1. **先读 AGENTS.md**：仓库根的 `AGENTS.md` 是入口规范，含目录结构、构建命令、安全红线。
2. **先读架构决策**：`doc/ARCHITECTURE.md` 记录了 14 个关键决策的理由与备选方案，改代码前确认你的方案不与既有决策冲突。
3. **符号级定位**：改功能先定位符号（类名/函数名），用 `SearchSymbol` 查调用关系，不要全文盲改。

## 目录纪律（红线）

| 目录 | 允许 | 禁止 |
|---|---|---|
| `src/` | `.ts` / `.vue` 源码 | 测试快照、临时脚本、构建产物、`node_modules` |
| `dev/` | 入库测试基建：mock 实测页 `dev/index.html` + `dev.js` 入口及其同目录 ES 模块（types/constants/state/log/mock/bundle/config/editor/runtime/layout），供他人测试/核对/验证 | 被忽略/移入 tmp、放敏感信息 |
| `tmp/` | 临时产物：构建产物/验证截图/一次性脚本/垃圾数据/缓存/日志/敏感信息 | 工程配置、入库源码、测试基建 |
| `doc/` | 文档 `.md` | 代码文件 |
| `img/` | 截图 `.png` | 代码文件 |
| 项目根 | `package.json` / `pnpm-lock.yaml` / `vite.config.ts` / `vitest.config.ts` / `tsconfig.json` / `node_modules/` / `README.md` / `AGENTS.md` / `.gitignore` | 临时产物 |

**工程文件位置红线**：`package.json` 等工程配置与 `node_modules/` 必须留在**项目根**（常规 Node 项目结构），**严禁移入 `tmp/`**。

## 安全红线（违反即返工）

1. **令牌/密钥绝不入库**：`.gitignore` 已排除 `tmp/HA_info.txt`、`tmp/HA_PROJECT_NOTES.md`、`tmp/tools/`、`tmp/ha_inventory/`。严禁 `git add -f` 强制添加。
2. **生产 HA 只读探测**：对 `http://192.168.31.205:8123` 只允许 GET 请求；写入实测必须在专用 `snoozepanel-test` 视图，完毕立即删除。
3. **不收集数据**：代码中严禁出现 `fetch` / `XMLHttpRequest` / `navigator.sendBeacon` 等外发请求（HA API 调用除外）。
4. **commit 需用户确认**：里程碑 commit 可做，但最终交付前必须用户确认，不擅自提交最终交付。

## 代码规范

### 分层铁律

- `src/core/`：**纯函数**，禁止 import DOM API（`document` / `window` / `localStorage` / `setTimeout` 等）
- `src/runtime/`：DOM/定时器/事件，依赖 core/ 纯函数
- `src/ui/` / `src/editor/`：Vue 组件，通过 `inject('snoozeState')` 取响应式状态

### 单文件行数约束（红线）

- **手写源码单文件 ≤ 520 行**（`src/**/*.{ts,vue}`、`dev/**/*.js`、工程配置 `*.config.ts` / `eslint.config.js`），超限必须按职责拆分。
- 由 `eslint.config.js` 的 `max-lines: ['error', 520]` 规则**强制**，`pnpm lint` 违规即报错，不得用 eslint-disable 绕过。
- 拆分原则：编辑器按「五区」拆子组件 + 组合式函数（`src/editor/components/`、`src/editor/composables/`）；dev 实测台按职责拆 ES 模块（`dev/`）。方案见 `doc/ARCHITECTURE.md` 决策 14。

### 配置持久化铁律

- **配置是用户资产，必须跨重启存活**：视图级配置随 lovelace 存储持久化；**设备级配置记录必须走后端持久化**（HA custom component + `.storage/`），**严禁用浏览器 `localStorage` 承载权威配置**——清缓存/换 App/HA 重启都会丢。方案见 `doc/ARCHITECTURE.md` 决策 9。
- 前端配置读写统一封装：优先 `hass.callWS()` 走后端，后端不可用时降级为视图 YAML 只读并给出提示。

### 新增配置项三步走

1. `src/core/types.ts`：声明类型 + 在 `DEFAULT_CONFIG` 给默认值
2. `src/core/config.ts`：`normalizeConfig` 中加校验/回退逻辑
3. `src/editor/forms/`：对应表单加输入控件（PrimeVue 中文 label）

### 注释与文档

- 代码注释、commit message、文档一律**中文**
- 关键函数写 JSDoc 风格注释：用途、参数、返回值、异常行为

### 测试纪律

- 新增 `src/core/` 函数必须配套 `src/tests/*.spec.ts`
- **禁止伪造测试输出**；自检报告必须贴 `pnpm test` 真实运行结果
- 测试命令：`pnpm test`（在项目根执行）

## 常用命令

```bash
pnpm install    # 装依赖（项目根执行）
pnpm build      # 构建 → tmp/dist/snoozepanel.js
pnpm test       # 跑单测
```

本地 mock 实测：
```bash
python -m http.server 8765
# 浏览器打开 http://127.0.0.1:8765/dev/
```

## 常见坑（血泪记录）

| 坑 | 原因 | 解法 |
|---|---|---|
| `pnpm install` 后报模块找不到 | 目录整体移动导致 pnpm 虚拟 store 链接失效 | 在项目根重跑 `pnpm install` 重建链接 |
| 产物浏览器报 `process is not defined` | vite define 未替换 process.env | `vite.config.ts` 已配 `define`，勿删 |
| 自定义元素注册报错 | 元素名不含连字符 | 必须用 `snooze-panel` 而非 `snoozepanel` |
| 改完代码屏保没变化 | 浏览器缓存 | Ctrl+F5 强刷 |
