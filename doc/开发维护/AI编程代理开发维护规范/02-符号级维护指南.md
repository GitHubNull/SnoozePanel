## 可机械执行的修改步骤

### 场景 1：新增一个配置项（如「屏保亮度上限」）

1. `src/core/types.ts`：`SnoozeConfig` 加 `brightness_limit?: number`，`DEFAULT_CONFIG` 加 `brightness_limit: 1`
2. `src/core/config.ts`：`normalizeConfig` 中加 `brightness_limit: clamp(raw.brightness_limit, 0, 1)`
3. `src/ui/ScreensaverApp.vue`：根容器 style 加 `filter: brightness(${config.brightness_limit})`
4. `src/editor/forms/`：基础表单加 Slider（0–1，步长 0.05），label「屏保亮度上限」
5. `src/tests/config.spec.ts`：加默认值/越界回退测试
6. `doc/使用教程/02-进阶配置.md`：补配置说明
7. `cd tmp && pnpm test && pnpm build`

### 场景 2：新增一个屏保组件（如「倒计时」）

1. `src/core/types.ts`：`SnoozeConfig.components` 加 `countdown?: { show: boolean; target: string; position: Position }`
2. `src/ui/components/CountdownView.vue`：新建组件，`inject('snoozeState')` 取 now
3. `src/ui/ScreensaverApp.vue`：模板加 `<CountdownView v-if="config.components.countdown?.show" />`
4. `src/editor/forms/ComponentsForm.vue`：加 countdown 分区
5. `src/tests/config.spec.ts`：加配置校验测试
6. `doc/使用教程/02-进阶配置.md`：补组件说明

### 场景 3：修改条件引擎（如 entity 条件支持 `not_state`）

1. `src/core/types.ts`：`EntityCondition` 加 `not_state?: string`
2. `src/core/conditions.ts`：`evalEntity` 加 `if (cond.not_state !== undefined) return entity.state !== cond.not_state`
3. `src/tests/conditions.spec.ts`：加 not_state 分支测试
4. `src/editor/forms/EntityConditionsForm.vue`：条件下拉加「状态不等于」
5. `doc/使用教程/02-进阶配置.md`：补条件说明

### 场景 4：修 bug（如「屏保激活后切换视图再切回，屏保消失」）

1. 定位：`SnoozeController` 的 `location-changed` 处理
2. 用 `SearchSymbol` 查 `location-changed` 的 `references`
3. 读 `src/runtime/controller.ts` 中相关逻辑
4. 复现：`cd tmp && python -m http.server 8765`，dev 页模拟
5. 修复后跑 `pnpm test` 确认无回归
6. mock 实测验证

## 调试技巧

**看屏保激活日志**：F12 控制台，`controller.ts` 关键路径有 `console.log`。

**看条件求值中间态**：在 `evalConditions` 入口加 `console.log('条件求值', { entity, time, sun })`。

**看 Vue 响应式状态**：F12 Console 执行 `document.querySelector('#snoozepanel-root').__vue_app__`。
