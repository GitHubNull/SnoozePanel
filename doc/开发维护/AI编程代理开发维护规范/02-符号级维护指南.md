## 可机械执行的修改步骤

### 场景 1：新增一个配置项（如「屏保亮度上限」）

1. `src/core/types.ts`：`SnoozeConfig` 加 `brightness_limit?: number`，`DEFAULT_CONFIG` 加 `brightness_limit: 1`
2. `src/core/config.ts`：`normalizeConfig` 中加 `brightness_limit: clamp(raw.brightness_limit, 0, 1)`
3. `src/ui/ScreensaverApp.vue`：根容器 style 加 `filter: brightness(${config.brightness_limit})`
4. `src/editor/panels/AppearancePanel.vue`（外观）或 `BasicPanel.vue`（基础）：加 Slider（0–1，步长 0.05），label「屏保亮度上限」
5. `src/tests/config.spec.ts`：加默认值/越界回退测试
6. `doc/使用教程/02-进阶配置.md`：补配置说明
7. `pnpm test && pnpm build`（项目根执行）

### 场景 2：新增一个屏保内容组件（如「倒计时」）

内容组件走 widgets 插件体系（放入目录即生效）：

1. `src/core/types.ts`：`SnoozeConfig.components` 加 `countdown`（含 `show/format/layout/color/options`），`DEFAULT_LAYOUTS` 补 `countdown`，`DEFAULT_CONFIG.components.countdown` 给默认值
2. `src/core/config.ts`：`normalizeConfig` 加 `countdown` 分支（show/format/layout/color/options），`FALLBACK_LAYOUTS` 补 `countdown`
3. `src/ui/widgets/countdown/index.vue` + `widget.meta.ts`：入口组件读 `WidgetProps.options`（参考内置 date/calendar）
4. `src/ui/ScreensaverApp.vue`：`placedComponents` 加 countdown 项（含 `type: 'countdown'` 与 `options`）
5. `src/editor/composables/useComponentSelection.ts`：`componentList` 加 countdown 项并补显隐 / layout / color 分支；`CategoryPanel.vue`（左栏）与 `PropertyPanel.vue`（右栏属性区块）随之适配
6. `src/core/store.ts`：`mergeConfig` 的 `components` 显式合并加 `countdown`
7. `src/tests/config.spec.ts` + `widgets.spec.ts`：加配置校验与挂载测试
8. 文档：`doc/使用教程/02-进阶配置.md` 与 `doc/开发维护/组件开发指南/04-专项指南/` 补组件说明

> 更简单的方式：第三方把组件目录整体放进 `src/ui/widgets/thirdparty/<id>/` 即生效，无需改 core/编辑器（但不会出现在编辑器分类区，需按需接入）。

### 场景 3：修改条件引擎（如 entity 条件支持 `not_state`）

1. `src/core/types.ts`：`EntityCondition` 加 `not_state?: string`
2. `src/core/conditions.ts`：`evalEntity` 加 `if (cond.not_state !== undefined) return entity.state !== cond.not_state`
3. `src/tests/conditions.spec.ts`：加 not_state 分支测试
4. `src/editor/forms/EntityConditionsForm.vue`：条件下拉加「状态不等于」
5. `doc/使用教程/02-进阶配置.md`：补条件说明

### 场景 4：扩展对齐 / 图层能力

1. 对齐/分布算法：`src/core/align.ts`（纯函数，`alignDeltas`/`distributeDeltas`），改动后补 `src/tests/align.spec.ts`
2. 图层算法：`src/core/layers.ts`（`reorderLayers`），补 `src/tests/layers.spec.ts`
3. 动作层：`useAlignmentActions.ts` / `useLayerActions.ts`（量测写回），`useEditorShortcuts.ts`（快捷键）
4. UI：`TopToolbar.vue` 菜单项；跨层接线 `editorContext.ts` 的 `EditorActionsKey` 与 `EditorApp.vue` 的 `provide`
5. 验证：`pnpm test` + dev 页真实多选（Ctrl 点选 2-3 个组件）→ 顶部工具条逐项验证

### 场景 5：修 bug（如「屏保激活后切换视图再切回，屏保消失」）

1. 定位：`SnoozeController` 的 `location-changed` 处理
2. 用 `SearchSymbol` 查 `location-changed` 的 `references`
3. 读 `src/runtime/controller.ts` 中相关逻辑
4. 复现：`python -m http.server 8765`（项目根），浏览器打开 `http://127.0.0.1:8765/dev/` 模拟
5. 修复后跑 `pnpm test` 确认无回归
6. mock 实测验证

## 调试技巧

**看屏保激活日志**：F12 控制台，`controller.ts` 关键路径有 `console.log`。

**看条件求值中间态**：在 `evalConditions` 入口加 `console.log('条件求值', { entity, time, sun })`。

**看 Vue 响应式状态**：F12 Console 执行 `document.querySelector('#snoozepanel-root').__vue_app__`。

**看表盘预览**：dev 实测台（`http://127.0.0.1:8765/dev/`）“表盘”卡片下拉展开即实时渲染；
原理是 100vw×100vh 舞台整体 `transform: scale`，新增表盘零适配。
