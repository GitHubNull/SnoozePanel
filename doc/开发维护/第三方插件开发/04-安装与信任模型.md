# 04 - 安装与信任模型

> 目标：说明插件包如何被安装进 SnoozePanel（两条通道）、安装链路的**前后端双重限额校验**、
> 以及必须向用户明示的**信任模型与安全边界**。
> 前置：[01-插件包格式与SDK.md](01-插件包格式与SDK.md)。

## 一、两条安装通道

市场工具栏「安装插件」按钮打开安装弹窗（`src/editor/PluginInstallDialog.vue`），含两个 Tab：

### 1. HA 本地目录

- 用户把插件目录放入 HA `config/www/snoozepanel/plugins/<id>/`（前端基址 `/local/snoozepanel/plugins`）；
- 弹窗填入**目录名（插件 id）**与**入口文件**（缺省 `index.js`），选择种类（表盘 / 内容组件）；
- 确认后：记录落盘（`channel: 'dir'`），运行时注入
  `<script src="/local/snoozepanel/plugins/<id>/<entry>">`，由插件自注册。

### 2. 文件上传

- 用户选择 `index.js`（**必需**）与 `plugin.json`（可选，用于自动填充 id / 种类 / 元数据）；
- **选择文件的当下即做类型 / 大小 / 内容校验**（见第三节），不通过立即拒绝并给出中文原因；
- 勾选信任提示后确认：记录落盘（`channel: 'upload'`，含 `code` 文本），运行时以
  `new Blob([code])` + `URL.createObjectURL` 注入 `<script src="blob:...">`。

两条通道**均同源 / 本地**，不引入任何外发请求。

## 二、安装链路

```
用户确认
  → 前端限额校验（体验层闸门）
  → hass.callWS('snoozepanel/install_plugin', { record })   # 后端强制校验 + 落盘 .storage/
  → loadPlugin(record)                                       # 注入 <script>，插件自注册
  → registerRuntimeFace / registerRuntimeWidget             # 写入运行时注册表
  → facesVersion / widgetsVersion 自增                       # 市场 / 下拉 / 预览自动刷新
```

- 记录写入后端 `.storage/`，**跨 HA 重启存活**（配置持久化红线，见架构决策 9）。
- 启动时由 `loadInstalledPlugins(hass)` 读取并加载全部「已启用」插件。
- 禁用（`enabled: false`）的插件启动时不加载；卸载仅从运行时注册表移除。

## 三、限额与校验（前后端双重防线）

限额口径由**单一常量源**定义：前端 `src/core/pluginLimits.ts`，后端 `custom_components/snoozepanel/const.py` 镜像，
dev mock 同步镜像，三者共用同一组数值与正则，避免口径漂移。

**定位**：前端是**体验层闸门**（可被绕过，仅用于即时反馈）；后端是**强制层**（服务端校验才是安全底线）。

| 维度 | 规则 | 前端校验 | 后端校验 |
|---|---|---|---|
| 类型白名单 | 仅允许 `index.js`（后缀 `.js`，MIME `application/javascript` / `text/javascript` / 空）；`plugin.json` 可选（后缀 `.json`） | `accept` + 后缀/MIME 二次校验 | `plugin.json.entry` 后缀必须 `.js`；`code` 仅接受校验通过的 `index.js` |
| 大小上限 | 单个 `.js` ≤ **512 KB**；`plugin.json` ≤ **64 KB**；单条安装记录总量 ≤ **1 MB** | `file.size` 预检，超限即拒并中文提示 | WS schema 对 `code` 长度硬限制（≤ 524288），超限报错 |
| 数量上限 | 已安装插件总数 ≤ **100** | 安装前 `checkPluginCount` 提示（覆盖同名 id 不受限） | 后端计数校验，超限拒绝 |
| 内容校验 | 拒绝空内容与含 NUL 字节（二进制）；`id` 必须匹配 `^[a-z0-9][a-z0-9-]{0,63}$`；`entry` 禁止 `..`、绝对路径、反斜杠 | 读取文本后基本校验（`checkScriptContent` / `isValidPluginId` / `checkEntryPath`） | voluptuous 严格类型/长度/正则校验，非法即拒绝 |
| 安全边界 | 后端**绝不执行**上传内容，仅存储；仅前端以 `blob:` 加载；不 `eval`、不写文件系统 | — | 只返回存储结果 |

前端校验函数（`src/core/pluginLimits.ts`，纯函数可单测）：

| 函数 | 用途 |
|---|---|
| `isValidPluginId(id)` | 校验插件 id 规则 |
| `checkScriptFile(file)` | 脚本类型白名单 + 512 KB 上限 |
| `checkManifestFile(file)` | 清单类型白名单 + 64 KB 上限 |
| `checkScriptContent(code)` | 拒绝空内容 / NUL 字节 |
| `checkRecordSize(scriptBytes, manifestBytes)` | 单条记录总量 ≤ 1 MB |
| `checkEntryPath(entry)` | 入口仅纯 `.js` 文件名，禁路径穿越 |
| `checkPluginCount(current)` | 数量上限 ≤ 100 |

设计要点：

- 错误提示**中文化**且不泄露内部路径；对超限 / 非法类型给出明确原因。
- `plugin.json` 缺省时允许由文件名/手动输入推断 `id`，但仍须通过 `id` 正则与大小校验。
- 存储层同时限制条目数（≤100）与单条大小，防止 `.storage` 被上传膨胀利用为 DoS。

## 四、信任模型

**第三方插件代码在 HA 页面以与宿主同等的完整权限执行**，可读取页面上的 `hass` 对象、
访问登录态下的数据。因此：

- 安装弹窗在**确认前**必须展示信任提示（上传通道需显式勾选），提醒用户「来源不可信时请勿安装」；
- 市场详情页应展示 `author` / `homepage` / `license` 等元数据，帮助用户判断来源；
- 只安装可信来源的插件；对来源不明的 `index.js` 保持怀疑。

## 五、安全边界与限制

- **不外发请求**：宿主红线禁止任何遥测 / 上报 / 外发（HA API 调用除外）；插件亦须遵守。
- **同源加载**：仅支持同源 `/local` 目录与本地 `blob:` 两通道，**不支持任意外网 URL**。
- **无法真正卸载**：同源脚本一旦执行，浏览器不允许移除；「卸载」仅从运行时注册表移除，
  彻底清理需刷新页面（重新注册同名 id 会覆盖旧注册）。
- **仅运行时注册**：后端只存储，不解析执行；插件生效完全依赖前端注入。

## 六、排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 提示「后端不可用，无法安装」 | 未连接 HA（无 `hass.callWS`） | 在 HA 环境内操作；本地用 dev 实测台 mock |
| 提示「保存失败：可能被后端限额拒绝」 | 触发后端强制校验（大小/数量/类型/正则） | 查看 HA 日志中 `snoozepanel` 记录，按提示修正 |
| 「记录已保存，但脚本加载 / 注册失败」 | `index.js` 未调用 `registerFace/registerWidget`，或入口路径错误 | 确认脚本末尾有注册调用；目录通道确认 `entry` 与文件一致 |
| 卸载后仍可见 | 同源脚本无法卸载 | 刷新页面 |
| 上传被即时拒绝 | 类型 / 大小 / 内容不合法 | 按提示的中文原因修正后重试 |
