# 02-目录契约与注册机制

> 目标：理解「放入目录即生效」的实现原理，知道内置 / 第三方如何归类、如何覆盖。

## 一、注册表在构建时扫描

内容组件注册表 [registry.ts](../../../../src/ui/widgets/registry.ts) 用 Vite 的 `import.meta.glob` 在**构建时**收集目录，运行时**零请求**（符合「不收集数据、不外发请求」红线）：

```ts
// 内置组件：widgets/<id>/index.vue（排除 thirdparty 子目录）
const builtinModules = import.meta.glob('./*/index.vue', { eager: true });
// 第三方组件：widgets/thirdparty/<id>/index.vue
const thirdpartyModules = import.meta.glob('./thirdparty/*/index.vue', { eager: true });
// 元数据（可选）
const metaModules = import.meta.glob('./*/widget.meta.ts', { eager: true });
```

`eager: true` 表示同步打包进单文件 IIFE 产物 `tmp/dist/snoozepanel.js`。

## 二、目录契约

| 位置 | 归类 `source` | 说明 |
|---|---|---|
| `src/ui/widgets/<id>/index.vue` | `builtin` | 系统内置 |
| `src/ui/widgets/thirdparty/<id>/index.vue` | `thirdparty` | 第三方安装 |
| `src/ui/widgets/<id>/widget.meta.ts` | — | 可选元数据 |
| `src/ui/widgets/thirdparty/<id>/widget.meta.ts` | — | 可选元数据 |

```
src/ui/widgets/
├── types.ts                  # WidgetProps / WidgetMeta 类型
├── registry.ts               # 注册表（无需改动）
├── calendar/ index.vue + widget.meta.ts
├── date/     index.vue + widget.meta.ts
├── lunar/    index.vue + widget.meta.ts
├── weather/  index.vue + widget.meta.ts
├── text/     index.vue + widget.meta.ts
└── thirdparty/
    └── <id>/ index.vue + widget.meta.ts   # 第三方安装区
```

- **入口组件必需**：`index.vue`；
- **元数据可选**：`widget.meta.ts`，缺省 `id` 取目录名、`label` 取 id；
- 目录内可自由拆分子组件 / `.ts` / `.css`，**注册表只认 `index.vue` 与 `widget.meta.ts`**。

### widget.meta.ts 字段

```ts
export default {
  id: 'diver-date',   // 可选：唯一 id，务必与目录名一致
  label: '潜水日期',   // 可选：中文显示名
};
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `id` | 可选 | 唯一标识；缺省取目录名。**与目录名一致**，避免引用混乱 |
| `label` | 可选 | 中文显示名 |

## 三、第三方覆盖内置

解析优先级：**第三方同 id 覆盖内置**。

若 `thirdparty/calendar/index.vue` 存在，则内置 `calendar/` 被替换，`getWidget('calendar').source === 'thirdparty'`。
这是「第三方可放目录整体替换内置组件」的实现方式，无需改任何注册代码。

## 四、对外 API

| 函数 | 返回 | 用途 |
|---|---|---|
| `getWidget(id)` | `WidgetMeta` | 按 id 取组件；未知 id 回退默认组件（`text`） |
| `listWidgets()` | `WidgetMeta[]` | 列出全部组件（按 id 字典序） |
| `hasWidget(id)` | `boolean` | 判断是否已注册 |
| `listWidgetOptions()` | `WidgetOption[]` | 纯数据摘要（id/label/source，不含组件引用） |
| `DEFAULT_WIDGET_ID` | `'text'` | 默认回退 id |

渲染层用 `getWidget(type).component` 动态挂载；数据摘要 `listWidgetOptions()` 可安全跨序列化边界传递（供编辑器/预览枚举）。

## 五、与「表盘（faces）」的关系

| | faces（表盘） | widgets（内容组件） |
|---|---|---|
| 目录 | `src/ui/faces/<id>/` | `src/ui/widgets/<id>/` |
| 元数据 | `face.meta.ts`（id/label/kind） | `widget.meta.ts`（id/label） |
| props | `FaceProps`（now/seconds/hour24/theme） | `WidgetProps`（now/hass/theme/options/color） |
| 归属 | 仅时钟 | 日历/日期/农历/天气/文本 |

两者**同一套「目录契约 + 构建时扫描」模式**，互不干扰。

## 六、验证机制

- 单测：`src/tests/widgets.spec.ts` 断言内置组件齐全、`source==='builtin'`、每个组件可挂载渲染；
- 真实 UI：临时放一个 `src/ui/widgets/thirdparty/<id>/` 覆盖目录，`pnpm build` 后确认渲染被替换，验证后移除。
