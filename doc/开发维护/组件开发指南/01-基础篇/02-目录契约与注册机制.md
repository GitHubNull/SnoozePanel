# 02-目录契约与注册机制

> 目标：理解「放入目录即生效」的实现原理，知道「类型 / 样式」两级目录如何归类、如何覆盖。

## 一、注册表在构建时扫描

内容组件注册表 [registry.ts](../../../../src/ui/widgets/registry.ts) 用 Vite 的 `import.meta.glob` 在**构建时**收集目录，运行时**零请求**（符合「不收集数据、不外发请求」红线）：

```ts
// 内置样式：widgets/<type>/<style>/index.vue（排除 thirdparty 子目录）
const builtinModules = import.meta.glob(['./*/*/index.vue', '!./thirdparty/**'], { eager: true });
// 第三方样式：widgets/thirdparty/<type>/<style>/index.vue
const thirdpartyModules = import.meta.glob('./thirdparty/*/*/index.vue', { eager: true });
// 元数据（可选）
const metaModules = import.meta.glob(['./*/*/widget.meta.ts', '!./thirdparty/**'], { eager: true });
```

`eager: true` 表示同步打包进单文件 IIFE 产物 `tmp/dist/snoozepanel.js`。

## 二、两级目录模型（类型 / 样式）

内容组件分「类型（type）」与「样式（style）」两级：

- **类型**：calendar / date / lunar / weather / text（决定数据结构与配置字段）；
- **样式**：同一类型下的多款外观（如日历的 basic / compact / minimal），用户可在「样式选择器」弹窗中切换。

| 位置 | 归类 `source` | 说明 |
|---|---|---|
| `src/ui/widgets/<type>/<style>/index.vue` | `builtin` | 系统内置样式 |
| `src/ui/widgets/thirdparty/<type>/<style>/index.vue` | `thirdparty` | 第三方样式 |
| `src/ui/widgets/<type>/<style>/widget.meta.ts` | — | 可选元数据 |
| `src/ui/widgets/thirdparty/<type>/<style>/widget.meta.ts` | — | 可选元数据 |

```
src/ui/widgets/
├── types.ts                  # WidgetProps / WidgetStyleMeta / WidgetStyleOption 类型
├── registry.ts               # 注册表（无需改动）
├── calendar/                 # 类型：日历
│   ├── basic/   index.vue + widget.meta.ts   # 样式：基础月历
│   ├── compact/ index.vue + widget.meta.ts
│   └── minimal/ index.vue + widget.meta.ts
├── date/     ...             # 类型：日期（basic / badge / stacked）
├── lunar/    ...             # 类型：农历（basic / pill / detail）
├── weather/  ...             # 类型：天气（basic / card / inline）
├── text/     ...             # 类型：自定义文本（basic / badge / quote）
└── thirdparty/               # 第三方安装区
    └── <type>/<style>/ index.vue + widget.meta.ts
```

- **入口组件必需**：`index.vue`；
- **元数据可选**：`widget.meta.ts`，缺省 `label` 取样式目录名；
- 目录内可自由拆分子组件 / `.ts` / `.css`，**注册表只认 `index.vue` 与 `widget.meta.ts`**。

### widget.meta.ts 字段

```ts
export default {
  label: '基础月历',   // 可选：中文显示名（缺省取样式目录名）
};
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `label` | 可选 | 中文显示名（样式选择器卡片用） |

> 类型（type）与样式（style）由目录路径解析得出，无需在元数据里重复声明。

## 三、第三方覆盖内置

解析优先级：**第三方同 `type + style` 覆盖内置**。

若 `thirdparty/weather/minimal/index.vue` 存在，则内置同名样式被替换，`getWidget('weather', 'minimal').source === 'thirdparty'`。

## 四、对外 API

| 函数 / 常量 | 返回 | 用途 |
|---|---|---|
| `getWidget(type, style?)` | `WidgetStyleMeta` | 按类型+样式取组件；style 缺省取该类型默认样式；type 未登记回退默认类型（`text`） |
| `listWidgetStyles(type)` | `WidgetStyleMeta[]` | 列出某类型全部样式（内置在前、第三方在后） |
| `hasWidget(type, style)` | `boolean` | 判断某 type+style 是否已注册 |
| `listWidgetTypes()` | `{ type; label }[]` | 列出全部类型（含中文名） |
| `listWidgetStyleOptions(type)` | `WidgetStyleOption[]` | 纯数据摘要（type/style/label/source，不含组件引用） |
| `WIDGET_TYPE_LABELS` | `Record<string, string>` | 类型 id → 中文名 |
| `DEFAULT_WIDGET_TYPE` | `'text'` | 默认回退类型 |
| `DEFAULT_WIDGET_STYLE` | `Record<string, string>` | 各类型默认样式 id（均为 `'basic'`） |

渲染层用 `getWidget(type, style).component` 动态挂载；数据摘要 `listWidgetStyleOptions(type)` 可安全跨序列化边界传递（供编辑器样式选择器枚举）。

## 五、与「表盘（faces）」的关系

| | faces（表盘） | widgets（内容组件） |
|---|---|---|
| 目录 | `src/ui/faces/<id>/`（单级） | `src/ui/widgets/<type>/<style>/`（两级） |
| 元数据 | `face.meta.ts`（id/label/kind） | `widget.meta.ts`（label） |
| props | `FaceProps`（now/seconds/hour24/theme） | `WidgetProps`（now/hass/theme/options/color） |
| 归属 | 仅时钟 | 日历/日期/农历/天气/文本 |

两者**同一套「目录契约 + 构建时扫描」模式**，互不干扰。

## 六、验证机制

- 单测：`src/tests/widgets.spec.ts` 断言每类型含 3 内置 + 1 第三方样式、`getWidget(type)` 回退 `basic`、遍历全部样式可挂载渲染；
- 真实 UI：临时放一个 `src/ui/widgets/thirdparty/<type>/<style>/` 覆盖目录，`pnpm build` 后确认渲染被替换，验证后移除。
