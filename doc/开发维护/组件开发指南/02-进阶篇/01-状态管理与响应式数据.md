# 01-状态管理与响应式数据

> 目标：让组件正确响应 `now` / `hass` / `options` 的变化，不引入冗余定时器。

## 一、数据从哪来：全部走 props

内容组件是**纯展示组件**，不自己取数据。所有运行时数据由外层经 `WidgetProps` 注入：

| Prop | 类型 | 更新时机 | 用途 |
|---|---|---|---|
| `now` | `Date` | **每秒**（外层 Ticker 驱动） | 时间/日期/农历 |
| `hass` | `HassLike` | HA 推送时 | 读实体状态（天气/文本） |
| `theme` | `Theme` | 主题切换 | 取色/字重 |
| `options` | `Record<string, unknown>` | 配置变更 | 该组件的配置项 |
| `color` | `string?` | 配置变更 | 自定义字体色 |

> **禁止**在组件内 `new Date()` 或 `setInterval` 自取时间——会和屏保的统一 tick 冲突，且多实例各跑一套定时器。

## 二、用 `computed` 派生，而非 `watch`

组件只需「随 props 变化重算出渲染内容」，用 `computed` 即可（Vue 自动追踪依赖）：

```vue
<script setup lang="ts">
import { computed } from 'vue';
import { formatDate } from '@/core/clock';
import type { WidgetProps } from '../types';

const props = defineProps<WidgetProps>();

// options.format 变化 → 自动重算
const format = computed<string>(() =>
  typeof props.options.format === 'string' && props.options.format
    ? props.options.format
    : 'YYYY年MM月DD日 dddd',
);

// now 每秒变化 → 自动重算文本
const text = computed(() => formatDate(props.now, format.value));
</script>

<template><div>{{ text }}</div></template>
```

要点：

- **读 `options` 要判类型**：`Record<string, unknown>`，用 `typeof x === 'string'` 收窄，缺失时给回退值；
- **不要 `watch` 去赋值 ref**：能 `computed` 就别用 `watch` + `ref`，减少中间态；
- **复杂计算抽到 `src/core/`**：纯函数无副作用、可单测（如 `formatDate` / `formatLunar` / `renderText`）。

## 三、读 `hass` 实体状态

`hass.states[entityId]` 返回实体对象（可能不存在）：

```ts
const info = computed(() => {
  const s = props.hass.states[entity.value];
  if (!s) return null;                       // 实体不存在 → 不渲染
  const temp = s.attributes.temperature;     // attributes 为 Record<string, unknown>
  return {
    condition: s.state,
    temperature: typeof temp === 'number' ? `${Math.round(temp)}°` : '',
  };
});
```

```vue
<template>
  <div v-if="info" class="weather">…</div>   <!-- 缺失时整块不渲染 -->
</template>
```

要点：

- **实体不存在时优雅隐藏**（`v-if`），不要抛异常；
- **数值属性判类型**（`typeof === 'number'`）再格式化；
- 复杂文本替换可复用 `src/core/text.ts` 的 `renderText`（见 [专项：自定义文本](../04-专项指南/自定义文本组件.md)）。

## 四、配置项读写（`options`）

`options` 是**只读透传位**，组件只读不写。用户的编辑入口在编辑器属性面板（写回 `components.<type>`），构建 `WidgetProps.options` 时由配置层合并注入。

- 组件内：只从 `options` 读（如 `options.format` / `options.entity`）；
- 编辑器内：由 `PropertyPanel` 写回草稿的对应字段；
- 两者的键名要对齐（见 [03-组件接口规范.md](../03-组件接口规范.md) 的配置结构）。

> 为什么时钟组件不同？时钟走 faces，props 是 `FaceProps`（`now/seconds/hour24/theme`），不是 `WidgetProps`。

## 五、生命周期与清理

内容组件**通常无生命周期需求**（不持有定时器/监听）。若确实要用：

```ts
import { onMounted, onBeforeUnmount } from 'vue';
onMounted(() => { /* 绑定 */ });
onBeforeUnmount(() => { /* 解绑，务必成对 */ });
```

约定：

- 绑定的事件/定时器**必须在 `onBeforeUnmount` 解绑**，否则反复激活/退出会内存泄漏；
- **优先用 `computed`**，尽量不写生命周期。

## 六、清单

- [ ] 不自己 `new Date()` / 不自己 `setInterval`，时间只用 `props.now`
- [ ] `options` 读取做了类型收窄 + 缺省回退
- [ ] 实体缺失时 `v-if` 优雅隐藏，不抛异常
- [ ] 能用 `computed` 的不用 `watch` + `ref`
- [ ] 复杂逻辑抽到 `src/core/` 纯函数并补单测
- [ ] 有副作用（事件/定时器）时 `onBeforeUnmount` 成对清理
