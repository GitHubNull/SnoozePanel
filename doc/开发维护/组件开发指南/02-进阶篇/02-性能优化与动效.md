# 02-性能优化与动效

> 目标：让组件在低功耗平板长时运行时不掉帧、不发热、不泄漏。

## 一、性能基线：屏保是长时运行的

屏保可能连续显示数小时，且每秒都会收到新的 `now`。性能红线：

- **每秒只做必要的重算**：`computed` 自动缓存，未变的依赖不重算；
- **不逐帧跑 JS 动画**：1s 才一次 `now`，靠 JS 逐帧动画会明显跳变；
- **不在模板里做重计算**：把计算放进 `computed`，模板只做展示。

## 二、连续机械运动交给 CSS `@keyframes`

齿轮、转盘这类**连续**运动不要靠 JS，交给 CSS 走合成层，稳定 60fps：

```css
.gear-spin {
  transform-box: fill-box;    /* SVG 元素以自身包围盒为参照 */
  transform-origin: center;   /* 绕自身中心旋转 */
  animation: gearSpin var(--dur, 60s) linear infinite;
}
@keyframes gearSpin { to { transform: rotate(360deg); } }

/* 无障碍：用户要求减少动态时停转 */
@media (prefers-reduced-motion: reduce) {
  .gear-spin { animation: none; }
}
```

- 传动比按齿数推导，啮合方向相反用 `animation-direction: reverse`；
- 相位对齐用一次性负 `animation-delay`（如 `-${now.getSeconds()}s`），避免每秒重置。

## 三、指针/数值跳变用 `transition` 平滑

若位置来自 `now`（每秒一次），可加轻量 `transition` 平滑过渡，而非自带 rAF：

```css
.hand { transition: transform 0.5s cubic-bezier(0.4, 2.3, 0.6, 1); }
```

## 四、SVG `<defs>` id 唯一化：用 `useId()`

同一组件会**同时**出现在「画布预览」与「全屏」中（多实例）。若 `<defs>` 的 id 写死（如 `id="grad"`），多实例互相串色：

```ts
import { useId } from 'vue';
const uid = useId();
const id = (n: string) => `${n}-${uid}`;
```

```vue
<defs>
  <linearGradient :id="id('grad')">…</linearGradient>
</defs>
<circle :fill="`url(#${id('grad')})`" />
```

> 命名与引用务必成对使用同一个 `id(...)`，否则会出现「有定义无引用」的空白。

## 五、减少重排与重绘

- 变换用 `transform` / `opacity`（走合成层），避免 `top/left/width` 触发布局；
- 大块背景/渐变抽到一次绘制，别逐帧改；
- 列表渲染加 `:key`，避免 Vue 复用错位。

## 六、无障碍：尊重 `prefers-reduced-motion`

所有持续动效都必须提供静态回退：

```css
@media (prefers-reduced-motion: reduce) {
  .animated { animation: none; transition: none; }
}
```

## 七、清单

- [ ] 无 JS 逐帧动画；连续动效用 CSS `@keyframes`
- [ ] 动画含 `prefers-reduced-motion: reduce` 静态回退
- [ ] 所有 `<defs>` id 用 `useId()` 加实例前缀且引用一致
- [ ] 变换优先 `transform`/`opacity`，避免频繁触发布局
- [ ] 重计算放 `computed`，模板只做展示
- [ ] `v-for` 有稳定 `:key`
