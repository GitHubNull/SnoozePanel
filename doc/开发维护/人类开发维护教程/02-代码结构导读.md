# 02-代码结构导读

> 面向人类开发者：读懂 SnoozePanel 的模块边界、数据流与生命周期。

## 分层架构

```
┌─────────────────────────────────────────┐
│  HA 视图 YAML（snoozepanel: 段）          │
└──────────────┬──────────────────────────┘
               │ setConfig / hass setter
               ▼
┌─────────────────────────────────────────┐
│  src/panel.ts（SnoozePanelElement）      │  门控：无配置/enabled=false/设备不允许 → 零副作用
└──────────────┬──────────────────────────┘
               │ 配置合法 → 启动控制器
               ▼
┌─────────────────────────────────────────┐
│  src/runtime/controller.ts               │  状态机：idle → active → cooldown
│  （SnoozeController）                    │  事件：pointerdown/touchstart/keydown/location-changed
└──────────────┬──────────────────────────┘
               │ 条件满足且闲置超时
               ▼
┌─────────────────────────────────────────┐
│  src/runtime/mount.ts                    │  创建 #snoozepanel-root 容器
│  （mountScreensaver）                    │  挂 Vue 子应用 + provide 响应式 state
└──────────────┬──────────────────────────┘
               ▼
┌─────────────────────────────────────────┐
│  src/ui/ScreensaverApp.vue               │  屏保根组件：背景/遮罩/九宫格/主题
│  ├── faces/（表盘注册表 + 各表盘目录）      │  按 style 表盘 id 动态解析
│  └── components/（日历/农历/天气/文本）     │
└─────────────────────────────────────────┘
               ▲
               │ 纯函数求值
┌──────────────┴──────────────────────────┐
│  src/core/（纯函数，无 DOM 依赖）          │
│  config / conditions / lunar / clock /   │
│  template / text / device / store        │
└─────────────────────────────────────────┘
               ▲
               │ hass.callWS（设备级配置读写）
┌──────────────┴──────────────────────────┐
│  custom_components/snoozepanel/（后端）   │  WS API + .storage/ 持久化
└─────────────────────────────────────────┘
```

## 模块边界

### core/（纯函数层）

**铁律**：禁止 import 任何 DOM API（`document` / `window` / `localStorage` 等）。全部函数无副作用，可单测。

| 模块 | 职责 | 关键导出 |
|---|---|---|
| `types.ts` | 配置类型 + 默认值 | `SnoozeConfig` / `DEFAULT_CONFIG` |
| `config.ts` | 配置规范化/校验 | `normalizeConfig(raw)` |
| `device.ts` | 设备 id 解析 | `resolveDeviceId` / `isDeviceAllowed` |
| `conditions.ts` | 条件引擎 | `evalConditions` / `evalEntity` / `evalTime` / `evalSun` |
| `lunar.ts` | 农历换算 | `solarToLunar` / `formatLunar` |
| `clock.ts` | 日期格式化 + 表盘指针角度 | `formatDate` / `formatClock` / `clockHands` / `dateSubDialAngle` / `weekdaySubDialAngle` |
| `template.ts` | 模板求值 | `evalTemplate` |
| `text.ts` | 占位符替换 | `replaceEntityPlaceholders` |
| `hass.ts` | HA 类型 | `HassLike`（含 `callWS`） |
| `store.ts` | 设备级配置读写封装 | `loadDeviceConfig` / `saveDeviceConfig` / `mergeConfig` |

### runtime/（运行时层）

负责 DOM、定时器、事件监听。依赖 core/ 的纯函数。

| 模块 | 职责 |
|---|---|
| `controller.ts` | 激活/退出状态机、闲置计时、冷却、事件绑定、screensaver_entity 双向同步 |
| `mount.ts` | Vue 子应用挂载/卸载、DOM 清理 |
| `preview.ts` | `mountFacePreview`：表盘缩略预览挂载封装（update/destroy 句柄，供非 Vue 环境/dev 页调用）|
| `ticker.ts` | 1s tick，后台标签页暂停 |

### ui/（屏保 UI 层）

| 模块 | 职责 |
|---|---|
| `ScreensaverApp.vue` | 屏保根：背景轮播、遮罩、九宫格布局、主题变量、组件显隐、按表盘 id 动态渲染时钟；编辑态额外渲染网格层 + 吸附参考线并透传点选 |
| `faces/registry.ts` | 表盘注册表：`import.meta.glob` 扫描 `faces/*/`，导出 `getFace` / `listFaces` / `hasFace` / `listFaceOptions`（纯数据摘要）|
| `faces/types.ts` | 表盘统一 props 接口 `FaceProps`（`now/seconds/hour24/theme`） |
| `faces/<id>/` | 各表盘目录（`index.vue` 入口 + 可选子组件/`face.meta.ts`），内置 digital/ring/analog/chrono/minimal/orbit |
| `components/FacePreview.vue` | 表盘缩略预览：100vw×100vh 舞台整体缩放（与全屏逐像素一致，新表盘零适配）|
| `components/ComponentWrapper.vue` | 组件包装：定位/尺寸/字体颜色 + 编辑态拖拽缩放（`selected`/`snap`/`gridStep`/`guide`）|
| `components/CalendarView.vue` | 日历 |
| `components/LunarView.vue` | 农历 |
| `components/WeatherView.vue` | 天气 |
| `components/CustomText.vue` | 自定义文本 |
| `themes.ts` | midnight / paper 主题变量 |

#### 新增一款表盘

1. 建目录 `src/ui/faces/<表盘id>/`；
2. 写入口组件 `index.vue`，`defineProps<FaceProps>()` 接收 `now/seconds/hour24/theme`；
3.（可选）写 `face.meta.ts` 导出 `{ label, kind }`（`kind` 为 `'digital'|'analog'`）；复杂表盘可拆多个子组件/ts/css 放同目录；
4. `pnpm build` 重新构建即生效——注册表用 `import.meta.glob` 自动收集，无需改任何注册代码。

### editor/（配置编辑器）

编辑器（`EditorApp.vue`）自成**五区布局**：插件菜单栏（顶，可收起）/ 组件分类选择区（左，可拖宽可收起）/ 屏保效果阅览与位置尺寸编辑区（中，网格 + 磁吸 + 拖拽缩放 + 点选联动）/ 组件属性编辑器（右，按选中组件动态切换）/ 插件状态栏（底）。菜单栏与状态栏属于插件自身，HA 卡片编辑弹窗、HA 侧边栏与 dev 实测台三宿主复用同一组件。

`EditorApp.vue` 仅作**瘦编排层**：编排五区子组件 + `Toast` + 表盘市场，持有预览 `snoozeState`/预览 `Ticker`、设备 id、UI 偏好与状态栏派生数据；编辑逻辑下沉到 `composables/`、五区视图拆到 `components/`，跨区共享的三份状态经 `editorContext.ts` 以 provide/inject 下发。

| 模块 | 职责 |
|---|---|
| `editor.ts` | `SnoozePanelEditorElement`：HA card editor 协议（setConfig / config-changed），注册 PrimeVue ToastService |
| `EditorApp.vue` | 编辑器根（瘦编排层）：五区子组件编排、预览 snoozeState + 预览 Ticker、设备 id、表盘市场开合、UI 偏好、状态栏派生；保存反馈 Toast |
| `editorContext.ts` | 共享上下文注入键：`EditorDraftKey` / `EditorLayoutKey` / `EditorSelectionKey` + `injectEditorDraft/Layout/Selection`（缺 provide 即报错）|
| `useEditorLayout.ts` | 编辑器 UI 偏好：面板宽度/收起 + 画布网格（显示/磁吸/步长）；`localStorage`（`snoozepanel.plugin.layout`，仅 UI 偏好），窄宿主自动收起 |
| `composables/useEditorDraft.ts` | 本地草稿 + 回声防护（props 回填期间跳过 emit）+ 300ms 防抖 `emit('change')` |
| `composables/useComponentSelection.ts` | 选中组件状态与派生：组件清单/中文名、显隐开关、新增/删除文本、当前 layout/color 读写、画布点选与拖拽回写 |
| `composables/useDeviceSave.ts` | 设备级保存：调 `saveDeviceConfig` + 成功/失败/异常 Toast 反馈 |
| `components/EditorMenuBar.vue` | 五区之菜单栏：品牌 / 菜单导航（自带单一 Popover + 内部 5 个 panels）/ 启用开关 / 保存到后端 / 收起态细条 |
| `components/CategoryPanel.vue` | 五区之组件分类区：列表项 + 显隐开关 + 添加文本 + 拖宽 resizer + 收起滑轨 |
| `components/EditorCanvas.vue` | 五区之预览画布：网格/磁吸/步长工具条 + `<ScreensaverApp>` |
| `components/PropertyPanel.vue` | 五区之组件属性区：按选中组件渲染时钟/日历/农历/天气/文本属性、布局 X/Y/宽/高、字体颜色、表盘选择卡片 |
| `components/StatusBar.vue` | 五区之状态栏：设备 id / 提示 / 保存态 |
| `editor.css` | 编辑器共享样式（panel-head/scroll/resizer/rail/field 等基础规则，供 EditorApp 与各子组件 `<style scoped src>` 复用）|
| `FaceMarketplace.vue` | 表盘市场模态：列内置/第三方表盘，选中后回写 `components.clock.style` |
| `panels/` | 菜单栏全局配置浮层：`BasicPanel` / `AppearancePanel` / `ConditionsPanel` / `DevicePanel` / `AdvancedPanel`（v-model 传入各自配置切片，避免直接改 prop）|
| `forms/` | 复用分区表单（`EntityConditionsForm.vue`）|

### custom_components/snoozepanel/（后端 custom component）

设备级配置的权威存储，落盘到 HA `.storage/snoozepanel`，跨重启存活。

| 文件 | 职责 |
|---|---|
| `manifest.json` | 集成清单（domain `snoozepanel`，`config_flow: false`） |
| `const.py` | 常量：DOMAIN / STORAGE_KEY / WS 命令类型 |
| `__init__.py` | `async_setup`：初始化 `SnoozeStorage` + 注册 WS 命令 |
| `storage.py` | 封装 `helpers.storage.Store`，按 `device_id` 分区读写 |
| `websocket.py` | WS 命令：`get_config` / `set_config` / `list_devices` / `delete_config` |

前端 `src/core/store.ts` 通过 `hass.callWS()` 调用上述命令；后端不可用时降级为仅用视图 YAML。

### dev/（本地实测台）

静态服务器直开（`python -m http.server 8765` → `http://127.0.0.1:8765/dev/`），无构建步骤。入口 `dev.js` 仅负责事件绑定与启动编排，逻辑拆到同目录 ES 模块（`// @ts-check` + JSDoc，由 `tsconfig.dev.json` 对 `dev/**/*.js` 做类型检查）。

| 文件 | 职责 |
|---|---|
| `dev/index.html` | 页面结构 + 内联样式（截图1结构：顶栏（可收起）/ 中部背板舞台 + 与顶底栏 16px 间隔 / 底栏（可拖高可收起）；Toast 容器）|
| `dev/dev.js` | 瘦入口：`bindEvents()`（运行时按钮/布局交互/全局 error·unhandledrejection/输入基准）+ `bootstrap()`（应用布局 → 加载产物 → 内嵌编辑器 → 设备列表 → 状态轮询）|
| `dev/types.js` | 跨模块共享 JSDoc typedef（`LogLevel`/`FaceOption`/`FacePreview*`/`SnoozeConfig`/`EditorHandle`/`TestApi`/`Mock*`/`PanelElementLike`）|
| `dev/constants.js` | 常量（屏保实体 / 冷却秒数 / 闲置秒数 / 产物 URL / 日志上限 / 布局 key / 底栏高度）|
| `dev/state.js` | 页面元素引用 `el` + 可变运行时状态 `state`（单一对象承载，规避 ESM 只读绑定）|
| `dev/log.js` | 分级日志 / Toast / 按钮 busy 态 |
| `dev/mock.js` | mock hass（weather/sun/input_boolean…）+ mock 后端（get/set/list/delete_config）+ 设备列表拉取渲染 |
| `dev/bundle.js` | 构建产物脚本加载（`?t=` 缓存穿透）+ 状态徽标 + 读取 `window.SnoozePanelTestApi` |
| `dev/config.js` | 运行时初始配置 `buildBaseConfig` + 编辑器当前配置 `currentConfig` |
| `dev/editor.js` | 内嵌真实编辑器（常驻单例）创建 + config-changed 桥接回填面板元素 |
| `dev/runtime.js` | 运行时生命周期：挂载/重新应用/触发/退出/卸载 + 状态徽标/按钮态/脏标记刷新 |
| `dev/layout.js` | 实测台 UI 布局偏好（顶栏收起 / 底栏拖高·收起 / `html.sp-dev-resizing`）|

关键机制：

- 产物加载：`<script>` 注入 `../tmp/dist/snoozepanel.js?t=Date.now()`（缓存穿透），失败给指引 + 重试按钮；
- 插件内嵌：`ensureEditor()` 将真实编辑器 `mountEditor` 挂到**背板元素** `#stage-board`，五区铺满背板；
- 触发/退出：mock 实体 `input_boolean.screensaver` 置位 + 重赋 `el.hass`，走生产同款 `SnoozeController.syncFromEntity` 通路；
- 布局记忆：顶栏收起 / 底栏高度·收起存 `localStorage`（`snoozepanel.dev.layout`，仅 UI 偏好），`bootstrap()` 最先应用防闪跳；拖拽期间 `html.sp-dev-resizing`；
- 可观测性：Toast（成功/失败/警告）+ 分级日志（含 window error / unhandledrejection 捕获，保证“控制台零报错”可自证）。

## 数据流

### 激活流程

```
用户停止操作
  → controller 闲置计时器累计
  → 每 5s 重估条件（evalConditions）
  → 条件满足且闲置超时
  → mountScreensaver(config, hass, deviceId)
  → 创建 #snoozepanel-root append 到 body
  → Vue 子应用挂载，provide('snoozeState', reactive({now, hass}))
  → Ticker 启动，每秒更新 state.now
  → 各组件 inject('snoozeState') 响应式更新
  → 若配了 screensaver_entity → callService turn_on
```

### 退出流程

```
用户触摸/按键
  → controller 捕获事件（capture 阶段）
  → 检查冷却期（exit_cooldown_seconds）
  → app.unmount() + 移除 #snoozepanel-root
  → Ticker 停止 + 清空全部监听器
  → 若配了 screensaver_entity → callService turn_off
  → 进入冷却期，冷却内忽略激活输入
```

### hass 更新流

```
HA 推送 hass 更新
  → panel.ts hass setter
  → controller.setHass(hass)
  → 若屏保中：更新 provide 的 state.hass（组件响应式刷新）
  → 若条件失效：立即退出屏保
```

## 生命周期

### SnoozePanelElement

| 钩子 | 时机 | 做什么 |
|---|---|---|
| `setConfig` | HA 解析卡片配置 | 存配置，读视图 `snoozepanel:` 段 |
| `hass setter` | HA 推送状态 | 转发给 controller |
| `connectedCallback` | 元素入 DOM | 门控检查 → 启动 controller |
| `disconnectedCallback` | 元素出 DOM | controller.destroy() 彻底清理 |

### SnoozeController

| 方法 | 职责 |
|---|---|
| `start()` | 绑定事件监听、启动闲置计时与条件重估 |
| `tryActivate()` | 条件满足且闲置超时 → activate() |
| `activate()` | mountScreensaver + Ticker + screensaver_entity on |
| `exit()` | unmount + 清理 + screensaver_entity off + 冷却 |
| `destroy()` | 彻底清理（视图切换/元素移除时调用） |
