# 01-环境搭建

> 面向人类开发者：从零搭建 SnoozePanel 本地开发环境。

## 前置软件

| 软件 | 版本要求 | 验证命令 |
|---|---|---|
| Node.js | ≥ 18 | `node -v` |
| pnpm | ≥ 8 | `pnpm -v` |
| Python | ≥ 3.8（跑本地 mock 服务器用） | `python --version` |
| Git | 任意 | `git --version` |

## 克隆与目录约定

```bash
git clone <仓库地址> SnoozePanel
cd SnoozePanel
```

**目录纪律（重要）**：
- **工程文件在项目根**：`package.json` / `pnpm-lock.yaml` / `vite.config.ts` / `vitest.config.ts` / `tsconfig.json` / `node_modules/` 都放在**项目根**，符合常规 Node 项目结构
- `src/` 只放 `.ts` / `.vue` 源码
- `dev/` 是**入库的 mock 实测页**（`dev/index.html` + `dev.js` 瘦入口及同目录 ES 模块），供他人测试/核对/验证，**随仓库开源**
- `tmp/` 是**唯一临时目录**：构建产物、验证截图、一次性脚本、垃圾/测试数据、敏感信息都放这里，一律不入 git

## 安装依赖

```bash
pnpm install
```

在**项目根**执行即可，依赖装在项目根的 `node_modules/`（常规 Node 结构，无 Junction）。

## 构建

```bash
pnpm build
```

产物：`tmp/dist/snoozepanel.js`（单文件 IIFE，约 686KB，gzip 约 171KB）。构建产物属临时文件，统一输出到 `tmp/dist/`。

## 跑测试

```bash
pnpm test          # 跑全部单测
pnpm test:watch    # watch 模式
```

测试用 Vitest + jsdom，覆盖 `src/core/` 全部纯函数（农历/条件/设备/模板/配置/时钟）。

## 本地 mock 实测

```bash
python -m http.server 8765
```

在项目根启动，浏览器打开 `http://127.0.0.1:8765/dev/`，可：
- 切换主题（深夜/宣纸）、时钟样式（数字/模拟）、背景类型
- 点「立即触发屏保」看效果
- 点「打开配置编辑器」看 PrimeVue 中文编辑器

mock 页在 `dev/index.html`（结构样式）+ `dev/*.js`（逻辑，含 mock hass 对象：weather/sun/input_boolean 等实体）。它是**随仓库开源的测试基建**，任何人 clone 后 `pnpm build` 即可打开核对/验证。

## 真机调试（连接生产 HA）

> ⚠️ 生产环境只读探测，严禁写入。

1. 把 `tmp/dist/snoozepanel.js` 拷贝到 HA 的 `www/` 目录
2. HA 资源里加 `/local/snoozepanel.js`
3. 在专用测试视图（如 `snoozepanel-test`）加配置实测
4. 完毕**删除测试视图**恢复原状

## 常见坑

**Q：`pnpm build` 报「Cannot find module 'primevue/config'」？**
A：依赖不完整，在项目根重跑 `pnpm install`。

**Q：改完代码屏保没变化？**
A：浏览器强刷（Ctrl+F5）清缓存；dev 页产物 URL 带时间戳防缓存，但 HA 资源 URL 不带。

**Q：`pnpm install` 后突然报模块找不到？**
A：通常是 `node_modules` 被整体移动导致 pnpm 虚拟 store 链接失效，在项目根重跑 `pnpm install` 重建链接即可。
