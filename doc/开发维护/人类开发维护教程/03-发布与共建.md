# 03-发布与共建

> 面向人类开发者：构建、测试、版本、HACS 发布流程与贡献规范。

## 构建

```bash
pnpm build
```

产物：`tmp/dist/snoozepanel.js`（单文件 IIFE，Vue/PrimeVue/CSS 全部内联）。

**构建检查清单**：
- [ ] 产物文件存在且体积在 800–860KB 区间（当前约 832KB，gzip 约 208KB）
- [ ] 产物中无 `process.env` 引用（浏览器会报错）
- [ ] 产物中注册了 `snooze-panel` 与 `snooze-panel-editor` 两个元素
- [ ] 产物含 `snoozepanel-bundle-css` loud 注释标记（`src/styles/bundle.css` 首行，压缩后保留；供 `core/styleMirror.ts` 在 shadow root 内识别本项目打包 CSS，缺失则生产侧边栏/编辑器无样式）

## 测试

```bash
pnpm test
```

**测试纪律**：
- 禁止伪造测试输出；自检报告必须贴真实运行结果
- 新增 `src/core/` 纯函数必须配套 `src/tests/*.spec.ts`
- 测试覆盖率目标：core/ 100%，runtime/ 与 ui/ 以 mock 实测为主

## 版本号

遵循语义化版本（SemVer）：
- `MAJOR`：配置格式不兼容变更
- `MINOR`：新增配置项/组件（向后兼容）
- `PATCH`：bug 修复

版本号**三处同步**（缺一即出事故）：
1. `package.json` 的 `version`
2. `custom_components/snoozepanel/manifest.json` 的 `version`——**前端产物缓存破除串的单一源**：后端 `_frontend_version()` 读它拼 `panel_custom` 的 `module_url` 查询串（`?v=<version>`）
3. `CHANGELOG.md` 新增对应版本条目

> ⚠️ `/local` 静态产物 `cache-control` 为 `max-age` 31 天：发版必须 bump 到**从未下发过**的版本串。复用旧串（即使内容已换）浏览器仍命中旧缓存；lovelace 资源 URL 也带同版本串，需同步更新（见下节）。

## commit 规范

格式：`类型: 中文描述`

类型：
- `feat` 新功能
- `fix` bug 修复
- `docs` 文档
- `test` 测试
- `refactor` 重构（不改行为）
- `chore` 构建/工具/依赖

示例：
```
feat: 新增农历组件干支显示
fix: 修复跨午夜时间条件判断错误
docs: 补充进阶配置 weather 字段说明
```

## HACS 发布流程

### 首次发布

1. 仓库根加 `hacs.json`：
   ```json
   {
     "name": "SnoozePanel",
     "filename": "snoozepanel.js",
     "homeassistant": "2023.1.0"
   }
   ```
2. GitHub 仓库打 Release，tag 为版本号（如 `v1.0.0`）
3. Release 附件上传 `snoozepanel.js`
4. 用户通过 HACS 自定义仓库添加

### 更新发布

1. 改版本号（三处同步，见上节）
2. `pnpm build` 重新构建
3. commit + 打 tag + push
4. GitHub 新建 Release，附件传新产物
5. HACS 用户会收到更新提示

## 自托管部署与缓存破除（/local 通道）

不走 HACS、直接把产物放 HA `config/www/` 的部署方式（本项目生产环境采用），发版步骤：

1. **bump 版本**（三处同步）→ `pnpm build`
2. **传产物**：`scp tmp/dist/snoozepanel.js <host>:<config>/www/snoozepanel/snoozepanel.js`，远端 `sha256sum` 与本地 `Get-FileHash` 比对一致
3. **传后端**（如有改动）：`custom_components/snoozepanel/` 下改动文件同路径 scp
4. **重启 HA**（如 `docker restart homeassistant`）：`module_url` 的版本查询串在集成 setup 时注册，不重启不生效
5. **同步 lovelace 资源 URL**：设置 → 仪表板 → 资源（或 WS `lovelace/resources/update`，键为 `resource_id`）把 snoozepanel 资源 URL 改为 `?v=<新版本>`；不改则仪表板侧（卡片 + GUI 编辑器）仍加载旧缓存代码
6. **验证**（真实 UI）：导航 `/snoozepanel` 截图确认三栏布局带样式；只读量测确认 `snooze-panel-sidebar` 有 `shadowRoot` 且内含 `style[data-snooze-mirror]`；控制台无报错；顺带确认仪表板屏保激活/退出正常

**坑位备忘**：
- 复用已下发过的版本串（如旧资源注册过的 `?v=0.11.0`）仍命中 31 天旧缓存 → 必须用新串
- HA Store（`.storage/`）延迟约 60s 写盘，保存后立即查文件不存在属正常，勿误判为 WS 通路故障
- 侧边栏/编辑器元素在 HA shadow 树内，外部 `document.querySelector` 选不中其内部节点，验证需 shadow 遍历

## 共建指南

### 提 Issue

- bug：附 HA 版本、浏览器、控制台报错截图、视图 YAML 配置
- 功能建议：说明使用场景与预期效果

### 提 PR

1. Fork 仓库，新建特性分支
2. 遵守目录纪律（见 [01-环境搭建.md](01-环境搭建.md)）
3. 新增 core/ 函数必须配测试
4. commit message 遵守规范
5. PR 描述说明改动点与自测情况

### 代码审查要点

- core/ 是否保持纯函数（无 DOM import）
- 新增配置项是否三处同步：`types.ts` 类型 + `DEFAULT_CONFIG` 默认值 + `normalizeConfig` 校验
- 是否有内存泄漏风险（定时器/监听器是否在 destroy 中清理）
- 文档是否同步更新

## 安全红线（贡献者必读）

- 严禁在代码中加入任何遥测/数据上报
- 严禁把任何真实令牌/密钥/内网地址提交进仓库
- 生产环境实测必须只读，写入仅限专用测试视图且完毕即删
